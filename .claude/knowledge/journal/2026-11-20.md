# Learning journal 2026-11-20

### 2026-11-20: Resources, networking and performance — Optimized Arrow row paths must be checked against the legacy converter across all value shapes
**Context:** PR #628 replaced Table.toArray() with direct per-batch vector converters, PR #633 added a fast path for Decimal128, and PR #637 hardened parity tests. Each test compares the new output with the legacy getObjectRows output for scalar, struct, list, map and dictionary-encoded columns. Dictionary decimals turned out to keep the legacy unscaled-string form.
**Rule:** When optimizing Arrow row materialization, assert deep equality with the legacy converter for scalar, nested (struct/list/map), null, empty and dictionary-encoded columns in both object and array row modes, and keep any legacy quirks you find instead of silently fixing them.

### 2026-11-20: Resources, networking and performance — Object-row fast paths need a fallback for duplicate, __proto__ or mismatched column names
**Context:** In PR #628, the direct-vector object-row path builds rows keyed by column name. It falls back to the Table path when names repeat, a name is `__proto__`, or Arrow field names or counts differ from the Thrift schema.
**Rule:** When building plain-object rows keyed by server column names, fall back to the old path (or use a safe key strategy) if names are duplicated, include `__proto__`, or do not line up with the Arrow fields.

### 2026-11-20: Errors, logging and telemetry — Prove the instrumented path ran before asserting a spy was not called
**Context:** PR #633's test checks the decimal fast path by stubbing `byteLength` getters and asserting they are not read for safe integers. It also asserts `vector.get` was called once per value, because otherwise the notCalled checks would prove nothing.
**Rule:** When a test asserts that a spy or getter was not called to show a fast path was taken, also assert that the stubbed inputs were actually used, and check that the slow-path cases do trigger the spy.

### 2026-11-20: Resources, networking and performance — Node Buffers from pools are views; respect byteOffset/length
**Context:** PR #627 dropped a copy by passing `response.buffer()` output straight to Arrow decoding. A test checks that a small pooled Buffer (where `buffer.byteLength` is larger than `length`) still decodes, and also tests subarray bodies.
**Rule:** When passing Node Buffers to downstream decoders without copying, test with pooled and subarray Buffers, and never read `buf.buffer` without applying `byteOffset` and `length`.

### 2026-11-20: Bot workflow and CI — Kernel e2e path filters must include backend-shared modules
**Context:** PR #628 changed lib/result/ArrowResultConverter.ts, which both backends use. It had to add lib/result/ and the shared e2e util to the kernel-e2e workflow's changed-files regex, because otherwise the kernel e2e tests would be skipped.
**Rule:** When changing code shared by the Thrift and kernel backends (e.g. lib/result/ or shared e2e utils), make sure the kernel-e2e workflow's path filter covers those paths so the kernel e2e suite actually runs.
