# Learning journal 2026-11-26

### 2026-11-26: Resources, networking and performance — Detach node-fetch body-reader listeners after buffering on pooled TLS sockets
**Context:** PR #634 found that a keep-alive https.Agent socket holds on to its first ClientRequest through Node core listener closures. Through node-fetch's request closure, that request keeps the Response, the body-reader 'data'/'end'/'error' listeners and the whole downloaded CloudFetch buffer alive. The fix records which listeners response.buffer() adds and removes only those in a finally block, leaving earlier listeners, later listeners and the constructor's late-error handler in place.
**Rule:** After response.buffer() on a pooled HTTPS keep-alive connection, remove only the stream listeners that the read call itself added, in a finally block, and leave pre-existing and constructor error handlers attached so late stream errors are still handled.

### 2026-11-26: Test design — Prove memory release with WeakRef and forced GC over a real keep-alive HTTPS agent
**Context:** In PR #634 the retention bug appears only with real node-fetch, a keep-alive https.Agent and a TLS socket that stays pooled. Plain HTTP and stubbed Responses never show it. The test generates a localhost certificate with openssl and skips when openssl is missing. It holds the downloaded batch in a WeakRef, checks that the socket is still in agent.freeSockets, then forces GC (v8.setFlagsFromString('--expose-gc') plus vm.runInNewContext('gc')) and asserts deref() is undefined.
**Rule:** Test buffer-retention fixes end to end over a real keep-alive HTTPS server and agent: assert the socket is still pooled, then confirm with WeakRef plus forced GC that the payload was collected, because mocked responses or plain-HTTP tests cannot reproduce socket-pinned retention.
